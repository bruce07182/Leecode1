Complexity

Complexity asks two separate questions as the input gets bigger:

Time — how much work?Auxiliary Space — how much extra memory?

Let n mean the input size. Start with the Basics. Open the deeper sections only when you need them.

Time Complexity

Level 1 · Basics

Count how the work grows

x = nums[0]                 # O(1)

for x in nums:              # O(n)
    ...

for x in nums:              # O(n²)
    for y in nums:
        ...

Quick rule: one lookup → O(1), one full scan → O(n), nested full scans → O(n²).

Ignore constants and smaller terms: O(2n) → O(n), O(n + 10) → O(n), O(n² + n) → O(n²).

Level 2 · Function calls — add or multiply?

A function call is not automatically O(1). Use the complexity of the work inside it.

nums.sort()                 # O(n log n)

Even though this is one line and one function call, sorting n values takes O(n log n).

Calls one after another → add

helper(nums)                # O(n)
helper(nums)                # O(n)
# O(n) + O(n) = O(n)

A call repeated inside a loop → multiply

for x in nums:              # n times
    helper(nums)            # O(n) each time
# n × n = O(n²)
Remember: sequential work → add. Nested/repeated work → multiply. Then keep the fastest-growing term.
Level 3 · Recursion — count the calls

For recursive code, ask: How many calls are made, and how much work does each call do?

def countdown(n: int):
    if n == 0:
        return
    countdown(n - 1)
# One chain of n calls → O(n) time

One recursive call that reduces n by 1 usually creates one chain of about n calls.

def fib(n: int) -> int:
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# Calls branch repeatedly → exponential time

Here one call can create two more calls, which create more calls. Without memoization, the work grows roughly exponentially: O(2ⁿ) is a useful simple upper bound.

Level 4 · Why DP can make recursion much faster

Many recursive problems repeatedly solve the same smaller problem. Dynamic programming saves or builds those results instead of recalculating them.

ApproachTimeAuxiliary Space
Plain branching recursionO(2ⁿ)O(n) call stack
MemoizationO(n)O(n)
1D DP arrayO(n)O(n)
Optimized rolling variablesO(n)O(1)

The exact complexity depends on the problem, but this is the common pattern for problems such as Fibonacci or Climbing Stairs.

Auxiliary Space Complexity

Level 1 · Basics

Count extra working memory

For this trainer, Auxiliary Space means extra working memory used by the algorithm as n grows. We exclude the required input and required return/output buffer.

count = 0
for x in nums:
    if x > 0:
        count += 1
# A few variables → O(1) auxiliary space
seen = set()
for x in nums:
    seen.add(x)
# seen can grow to n items → O(n) auxiliary space
Quick rule: a fixed number of variables → O(1). An extra list/set/dict that can grow with n → O(n).
Level 2 · Input, output, and temporary memory

Required output is described separately

def keep_evens(nums: list[int]) -> list[int]:
    result = []
    for x in nums:
        if x % 2 == 0:
            result.append(x)
    return result

The returned result can contain n values, so output size is O(n). Under this trainer's convention, that required output buffer is excluded from Auxiliary Space.

Temporary memory still counts

temp = nums.copy()          # extra n-sized copy
return temp[0]
# Auxiliary Space: O(n)

temp is working memory rather than the required output, so it counts.

Because “space complexity” is used differently by different sources, in an interview it is safest to say exactly what you mean: “O(1) auxiliary space, excluding required input/output.”

Level 3 · Recursion uses auxiliary space

Recursive calls stay on the call stack until they return. For space, count the maximum number of calls alive at the same time, not the total number of calls.

def countdown(n: int):
    if n == 0:
        return
    countdown(n - 1)
# Maximum stack depth ≈ n → O(n) auxiliary space

This is why code can use O(n) auxiliary space even when it creates no list, set, or dictionary.

Important: exponential time does not mean exponential stack space

The naive Fibonacci recursion makes exponentially many calls over time, but its deepest active chain is only about n calls. So its time is exponential while its recursion-stack auxiliary space is O(n).

Level 4 · 1D DP space 
dp = [0] * (n + 1)
# n-sized working table → O(n) auxiliary space

If each new state only needs a few previous states, the table can sometimes be replaced by a fixed number of variables:

prev2 = 1
prev1 = 1
for i in range(2, n + 1):
    current = prev1 + prev2
    prev2 = prev1
    prev1 = current
# Fixed number of variables → O(1) auxiliary space

This changes the auxiliary space from O(n) to O(1) while keeping O(n) time.

Final checklist

Time: What work repeats as n grows? If you call another function, include its cost.

Auxiliary Space: What extra working memory grows with n? Include temporary structures and recursion stack; exclude required input/output.

Output: If useful, state its size separately.
