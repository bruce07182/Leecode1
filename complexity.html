Complexity

Complexity tells you how your code grows when the input gets bigger. Let n be the input size.

Time O(...): how much work?

Look at the code and ask: How many times can this work run as n grows?

x = nums[0]                 # O(1)

for x in nums:              # O(n)
    ...

for x in nums:              # O(n²)
    for y in nums:
        ...

# Repeatedly cut the problem roughly in half: O(log n)
# Sorting: usually O(n log n)

Ignore constants and smaller-growing terms: O(2n) → O(n), O(n + 10) → O(n), O(n² + n) → O(n²).

Auxiliary Space O(...): how much extra working memory?

For this trainer, Auxiliary Space means extra working memory the algorithm needs as input grows. Do not count the required input or required return/output buffer.

count = 0
for x in nums:
    if x > 0:
        count += 1
# A few variables: O(1) auxiliary space
seen = set()
for x in nums:
    seen.add(x)
# seen can grow with n: O(n) auxiliary space

Temporary lists, sets, dictionaries, stacks, queues, copies, and the recursion call stack count when they grow with n.

What about returned output?

def keep_evens(nums: list[int]) -> list[int]:
    result = []
    for x in nums:
        if x % 2 == 0:
            result.append(x)
    return result

The required returned result can grow to O(n). We describe that separately as output O(n). Under this trainer's convention, the return buffer itself is not auxiliary working memory.

This distinction matters because the phrase space complexity is not used identically everywhere. In an interview, the safest wording is to state what you are counting, for example: “O(1) auxiliary space, excluding the required output.”

Recursion counts too

def factorial(n: int) -> int:
    if n <= 1:
        return 1
    return n * factorial(n - 1)

There may be n unfinished calls on the call stack, so the recursion uses O(n) auxiliary space.

Quick check

Time: What work grows as n grows?
Auxiliary Space: What extra working memory grows as n grows?
Output: How large is the required returned result?
