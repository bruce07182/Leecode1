Files store information. CSV uses rows and columns; JSON uses named fields and nested structures. A database manages information with queries, relationships, and reliable updates. JSON itself can be saved as a file or stored in a database.

Deep dive · other file formats

Plain text: flexible but often requires custom parsing. Fixed-width: fields occupy fixed character positions; common in older business systems. Binary: compact machine-readable records. Indexed/sequential files (ISAM): file organization with indexes for efficient lookups. XML: structured tagged documents. CSV and JSON: widely used for exchange and storage. JSON and XML became popular after relational databases existed, not as historical predecessors.

Deep dive · short database history
1950s–1960s · File processing

Applications stored records in files, often with custom layouts and indexes.

1960s · Early databases

Hierarchical and network systems made related records easier to manage.

1970 · Relational model

Edgar F. Codd proposed a relational approach that influenced modern SQL databases.

1970s–1980s · SQL

SQL emerged from IBM research and became a standard for relational databases.

1990s–today · Web and cloud

Open-source, document, distributed and managed cloud databases grew alongside SQL systems.

Deep dive · keys, indexes and transactions

Primary key: identifies a row. Foreign key: connects orders to customers. Index: speeds up some lookups. Transaction: groups changes so they succeed or fail together.

How to design a database · tables and relationships

1. Identify entities: customers, orders, products. 2. Give each table a primary key. 3. Store a customer ID in orders as a foreign key instead of repeating customer details. 4. Pick data types and constraints. 5. Add indexes when queries need them.

Design rule: one fact should generally have one authoritative home. Avoid repeating customer names in every order; use JOIN when you need both.
